# Public-proposal table grammar

## Native Word requirement

Use Word-native tables for all text-heavy content. Set fixed DXA geometry: `tblW`, `tblInd`, `tblGrid`, and every `tcW` must agree. Repeat header rows and avoid fixed row heights.

## Visual tokens

- Number and title: `표 Ⅲ-2. 과제별 데이터 확보·검증 기준`.
- Add one sentence stating the question answered by the table.
- Header fill: light gray or 8-12% navy.
- Outer border: 0.8 pt; major separator: 0.65 pt; inner border: 0.38 pt.
- Body: 7.9 pt at 1.32 lines. Cell padding: 2 mm vertical/horizontal; compact exception 1.4 mm vertical and 1.6 mm horizontal.
- Align prose left; align numbers, dates, durations, and scores right or center.
- Use merged cells only for classification headers.
- Do not zebra-stripe rows.
- Express status with text: `확인`, `잠정`, `미확인`, or `차단`; never use color alone.
- Add source, date, and notes below the table.

## Allowed table types

1. Requirement - answer - evidence.
2. Baseline - gap - implication.
3. Work package - method - output - acceptance criterion.
4. Candidate - technology - data - implementation.
5. Schedule, RACI, risk, or KPI management.
6. Official annex and evidence binding.

## Official forms

Do not apply the analytical table style to an official annex. Preserve wording, fields, field order, signature/stamp area, and notes. Compare the completed form against a render of the original issuer form.
